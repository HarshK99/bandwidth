## Keep phase handoffs short and write them once.
### Handoffs should help the next chat start, not retell the session.
- Record status, changed files, checks, open issues, and next phase.
- Include the update in the phase commit. No extra commit just to record its own commit number.
- Give a short completion message and stop.

## Establish the app's job before importing a broader system.
### A source document provides context; it does not automatically define feature scope.
- We initially expanded Bandwidth toward journals and results tracking before confirming its narrower purpose.
- Agree on what stays outside the app before designing data or screens.

## Prototype changes within the interface the user already values.
### A simplified preview can accidentally suggest removing existing features.
- Preserve the timeline and existing components when demonstrating new behaviour.
- Clearly distinguish an interaction example from the proposed final screen.

## Reduce unnecessary choices before hiding them.
### Collapsing a long list improves presentation but does not simplify the underlying work.
- Combine overlapping activities and remove redundant categories.
- Add nesting only when it offers useful choices, such as Hobbies → Painting / Crossword / Language.
